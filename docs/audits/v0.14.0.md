# v0.14.0 Reliability Audit

Baseline: `e3f678e`, v0.13.1. Audit started 2026-09-05.

This is a binary terminal multiplexer, not an embeddable Rust UI library.
Universal terminal compatibility and superiority over tmux/Zellij are not
release claims. Readiness is based on reproducible tests and explicit limits.

## Scope and Release Gates

- PTY lifetime, streaming terminal parsing, keyboard negotiation, mouse reports.
- Attach/detach, slow or disconnected peers, readonly clients, SSH PTYs.
- Layout, borders, zoom, Unicode rendering, copy/search, clipboard.
- Config, project trust, snapshots, hooks, and bounded allocations.
- Server wiring, inactive tabs, restart policy, transactional mutation.
- CLI smoke tests, real integration tests, all-feature lint, actual MSRV,
  release artifacts and registry verification.

## Confirmed Baseline Findings

- Inactive tabs are not drained by the server loop; their processes can block
  once the PTY reader queue fills.
- Prefix detach targets every writable client instead of its originating client.
- A generic attach failure can unlink a live session socket.
- Startup spawns the active snapshot tab twice for multi-tab restores.
- IPC snapshot load kills the current session before attempting replacement.
- Interactive and internal CLI parsers differ, including unchecked grid
  multiplication and silently accepted unknown server flags.
- Automatic project/Procfile startup executes repository commands without an
  explicit trust decision.
- The optional render-diff feature is not connected to rendering and produces
  all-feature dead-code warnings. Default-feature CI does not catch them.

## Behavioral Changes

- Project commands and automatic Procfile startup require `--trust-project`.
  The read-only doctor checks syntax without executing or resolving secrets.
- Standard shell editing controls pass through unless explicitly rebound.
  Copy-mode query input, paste and close confirmations retain modal behavior.
- Split/layout/load operations validate and stage changes before replacing
  current state. Reflow preserves live processes; restoring a snapshot starts
  new processes and does not duplicate the active tab.
- Inactive PTYs continue draining. Writable clients determine shared geometry;
  smaller readonly clients receive clipped frames without shrinking writers.
- Snapshot files are private and bounded before execution. Externally expanded
  panes omit all metadata and history, intentionally restoring a clean shell.
- Reload applies settings, keymaps and hooks from the same checked bytes while
  preserving runtime-only settings and trusted project hooks.
- Hooks use four workers and a 64-job queue with bounded capture, private logs,
  cancellation and process-group cleanup. Capacity exhaustion is reported,
  not converted into unbounded threads or queued work.

## Reproduced Release Blocker: Output Bursts

An earlier five-minute run passed, but the subsequent final-candidate soak
failed. That earlier pass was not reused to declare the final candidate ready.
With five 1 MiB output producers, the daemon remained alive while the client
exited with `server connection lost`; the next PTY write returned EIO.

The capture harness's repeated 4 MiB copies were replaced by a bounded ring,
but the failure remained. Separate default and all-feature release binaries
then reproduced the same disconnect at approximately five seconds. Tracing
showed the 64-frame channel full at only 182136 and 4617 queued bytes,
respectively, far below its approximately 16 MiB byte budget.

The fix preserves ordered framed bytes in coalesced blocks, retains the byte
budget and two-second writer deadline, and removes the independent frame-count
failure. A regression queues 4096 small frames with the consumer paused and
verifies every frame followed by detach. It failed before the fix and passes
after it. Server rendering now retains pending dirty state across an 8 ms
cadence while continuing to drain PTYs; incremental ANSI frames are never
dropped. Identical PTY resizes no longer emit redundant ioctls.

Output failures now take the ordinary disconnect path so geometry and last-client
autosave are not skipped. Pending dirty panes remain deferred during synchronized
output, including clipped readonly frames; the existing explicit resize/UI full
redraw exception is unchanged. A short default/all-feature run passed after the
queue fix, but later source changes still require fresh final artifacts.

Actual terminal logs also exposed obsolete Ctrl+D/E and Ctrl+N status hints.
CLI/help/status labels now describe the current prefix bindings and F1 settings.
A real direct-mode PTY regression reproduced swallowed Ctrl+W editing, and passes
after removing that interception. These are checked separately from daemon mode.

## Remaining Limits

- No native Windows support or universal terminal/SSH compatibility claim.
- A TERM-value/PTY test is not a real GUI emulator/version matrix. WAN latency,
  remote reboot and SSH server policy differences remain environment-specific.
- No completed 24-hour soak or matched tmux/Zellij benchmark. Proxy allocation
  benchmarks are not measured daemon RSS or proof of zero memory leaks.
- Snapshot history is sanitized text, not complete attributes, alternate-screen
  state, process memory, or a resumable remote process after reboot.
- Kitty keyboard support is partial; image protocols, complete hyperlink
  metadata and full tmux command compatibility are not provided.
- UI palette depth comes from the daemon environment, not full independent
  capability negotiation for heterogeneous attached terminals.
- Runtime mouse coverage and the full manual emulator matrix need expansion;
  passing aggregate coverage floors does not close those gaps.
